Лабораторная работа №1. Интерфейс приложения и каркас frontend

Цели лабораторной работы

1. Определить основные экраны и пользовательские сценарии проекта.
2. Создать первоначальную версию интерфейса на React + TypeScript с использованием
   библиотеки UI-компонентов.

Задания

1. Назначение приложения, пользовательские сценарии и экраны

Люди, потерявшие животное, и люди, нашедшие чужое животное, часто не могут найти друг
друга. 

Мой сайт решает эту задачу , один пользователь публикует объявление с фотографией, а тот,
кто нашёл животное, может загрузить свою фотографию и получить список визуально похожих
объявлений.

Основные пользовательские сценарии:

 1  Потерял животное - ищу его по фото - ИИ-поиск по фото (`/search`) 
 2  Нашёл животное - размещаю объявление о находке - Разместить объявление (`/pets/new`) 
 3  Потерял животное - сообщаю об этом - Разместить объявление (`/pets/new`) |
|4  Просматриваю все объявления, фильтрую по статусу/виду/городу - Лента объявлений (`/feed`) |
 5  Открываю карточку животного, читаю описание, звоню автору - Карточка животного (`/pets/:petId`) |
 6  Управляю своими объявлениями - Личный кабинет (`/profile`) 

Необходимые экраны:

Главная страница - на ней мы знакомимся с сервисом, объясняется принцип работы, показывает свежие объявления 
ИИ-поиск по фото -  осуществляется загрузка фотографии и просмотр похожих объявлений 
Лента объявлений - список всех объявлений с фильтрами по статусу, виду и городу 
Карточка животного - полное описание объявления и контакты автора 
Разместить объявление - форма публикации объявления о потере/находке с валидацией 
Личный кабинет - данные пользователя и список его объявлений 
Вход и Регистрация - формы аутентификации 

2–3. Frontend-приложение, структура компонентов, вёрстка и маршрутизация

Приложение создано на React 18 + TypeScript через Vite. 
Клиентская маршрутизация
реализована на React Router 6  — переходы между всеми экранами работают
без перезагрузки страницы.
На этом этапе используются демонстрационные данные из
`src/entities/pet/mockPets.ts`, загрузка фото и «поиск» на странице  имитируются на
клиенте .

Структура проекта:

```
src/
  entities/          # доменные данные (типы и мок-данные животных, пользователя)
    pet/
    user/
  components/
    layout/          # шапка, общий каркас страницы
    PetCard.tsx       # переиспользуемая карточка объявления
  pages/             # экраны приложения 
  shared/
    theme/           # тема MUI: цвета, типографика, стили компонентов
  App.tsx            # маршрутизация
  main.tsx           # точка входа, подключение провайдеров
```
4. Библиотека UI-компонентов

Используется MUI (Material UI) 5 — единая тема оформления задана в
`src/shared/theme/theme.ts`: фирменные цвета, типографика (шрифты Fraunces и Manrope через
Google Fonts), скругления, стили кнопок и статусных плашек. 

5. Проверка запуска и навигации

Запуск проверен локально (`npm run dev`), переходы между всеми экранами через шапку сайта
и внутренние ссылки работают. Инструкция запуска — в разделе ниже.

Технологический стек

- React 18 + TypeScript — интерфейс приложения
- Vite — сборка и dev-сервер
- React Router 6 — клиентская маршрутизация
- MUI (Material UI) 5 — библиотека UI-компонентов и тема оформления

Установка и запуск
```bash
npm install
npm run dev
```
Приложение откроется на http://localhost:5173 .

# Лабораторная работа №2. Backend, API и работа с базой данных

## Цели лабораторной работы

1. Организовать серверную часть проекта на FastAPI.
2. Реализовать модель данных и CRUD-операции с использованием PostgreSQL и SQLAlchemy.

## Задания

### 1. Структура backend

Код разделён по назначению: маршруты принимают запрос и вызывают операции с данными,
операции работают с моделями, а входные и выходные данные описаны схемами.

```
backend/
  app/
    api/             # маршруты API: users.py, pets.py, listings.py
    models.py        # модели SQLAlchemy
    schemas.py       # схемы валидации запросов и ответов
    crud.py          # операции с данными и бизнес-логика
    database.py      # подключение к БД и сессии
    config.py        # конфигурация из переменных окружения
    main.py          # создание приложения, CORS, подключение роутеров
  tests/             # автотесты API
  .env.example       # пример настроек без секретов
  docker-compose.yml # локальная PostgreSQL
  requirements.txt
```

### 2. Подключение PostgreSQL и конфигурация

PostgreSQL подключена через SQLAlchemy. Параметры подключения вынесены в файл `.env`,
который не попадает в Git. В репозитории лежит только пример `.env.example` без секретов.

### 3. Модель данных

```
users 1 ──pets 1 ── pet_photos
  │           
  └────────────────── listings (author_id)
```

| Таблица | Назначение |
|---|---|
| `users` | пользователи: email , имя, телефон, город |
| `pets` | питомцы из профиля пользователя |
| `pet_photos` | фотографии питомцев |
| `listings` | объявления «потерян» / «найден» |

При удалении пользователя удаляются его питомцы, фото и объявления. При удалении питомца
удаляются его фото, а объявления остаются, у них `pet_id` становится `NULL`.

### 4. CRUD-операции

| Ресурс | Запросы |
|---|---|
| Пользователи | `POST /users`, `GET /users`, `GET` / `PATCH` / `DELETE /users/{id}` |
| Питомцы | `POST` / `GET /users/{id}/pets`, `GET` / `PATCH` / `DELETE /pets/{id}` |
| Фото | `POST /pets/{id}/photos`, `DELETE /pets/{id}/photos/{photo_id}` |
| Объявления | `POST /listings`, `GET /listings`, `GET` / `PATCH` / `DELETE /listings/{id}` |

Документация со всеми запросами открывается на http://localhost:8000/docs.

### 5. Валидация и обработка ошибок

| Код | Когда |
|---|---|
| 400 | пустой файл, чужой питомец в объявлении |
| 404 | запись не найдена |
| 409 | email уже занят |
| 413 / 415 | файл слишком большой / неподдерживаемый тип |
| 422 | некорректные данные (email, телефон, вид животного, дата в будущем) |

Ошибки возвращаются в виде `{"detail": "понятное сообщение"}`.

### 6. Проверка

Запущены автотесты (`pytest -v`): 18 тестов проходят. Они проверяют CRUD, фильтры, коды
ошибок и каскадное удаление. Таблицы `users`, `pets`, `pet_photos`, `listings` созданы в
PostgreSQL, данные сохраняются и читаются через API.

## Технологический стек

- FastAPI: HTTP API и документация Swagger
- SQLAlchemy 2.0: ORM
- PostgreSQL 16: база данных
- Pydantic 2: схемы валидации и настройки

## Установка и запуск

Требуется Python 3.11+ и Docker .

```bash
cd backend
python -m venv .venv
source .venv/bin/activate       
python -m pip install -r requirements.txt
docker compose up -d             # PostgreSQL на порту 5433
python -m uvicorn app.main:app --reload
```

В `.env` должны быть заданы `POSTGRES_PASSWORD` и `DATABASE_URL` с тем же паролем и портом
5433. Таблицы создаются
автоматически при запуске приложения. API откроется на http://localhost:8000.

Запуск тестов:

```bash
python -m pytest -v
```
